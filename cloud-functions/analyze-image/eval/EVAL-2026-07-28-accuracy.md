## 오답 5건 — 전부 p.147

```
10.user_answer     gt=["1","2"]                   pred="2"
10.correct_answer  gt=["1","2"]                   pred="2,4"
14.user_answer     gt=["beetween","in","along"]   pred="between|in|along"
15.user_answer     gt="3"                         pred="4"
15.correct_answer  gt="3"                         pred="5"
```

### A. 복수정답 미인식 (2건 — Q10)

발문은 **"어법상 알맞은 문장 두 개를 고르세요"**, 해설지 정답 `①,②`. 학생도 ①·② 각각에 연필 사선을 그었다.
모델은 user를 `2` 하나로만 읽었고, correct는 `2,4`라는 엉뚱한 집합을 냈다.

프롬프트에는 복수정답 지시문이 이미 상세히 있다(`buildStructurePrompt`). 문제는 **트리거 예시**다.

```
"모두 고르시오", "정답 2개", "(단, 2개)", "all that apply"
```

이 목록에 **"두 개를 고르세요"가 없다.** 개수를 한글 수사로 적은 형태를 모델이 패턴에서 놓친 것으로 보인다.

### B. 철자 자동교정 (1건 — Q14)

학생이 `beetween`이라 잘못 썼는데 모델이 `between`으로 **고쳐서** 전사했다.

학습 앱에서 이건 단순 오독보다 나쁘다 — **학생의 철자 오답이 정답으로 둔갑한다.** 틀린 걸 틀렸다고
알려주는 게 이 앱의 목적인데 그 근거가 사라진다.

프롬프트에 "지문은 요약·절삭 없이"는 있지만 **학습자 답안을 원문 그대로 전사하라는 지시가 없다.**
모델의 기본 성향은 교정이다.

빈칸 단위로 보면 3칸 중 2칸(`in`·`along`)은 정확히 읽었다 — `blank_cell` 집계가 이걸 잡아냈다
(문항 단위만 봤으면 "그냥 틀림"으로 뭉개졌다).

### C. 단일 객관식 오독 (2건 — Q15)

GT `3`인데 user `4`, correct `5`. 라벨 노트: *"③ 위에 연필 체크. 지문 빈칸 ⓐ~ⓓ는 학생이 비워뒀고
그 위의 필기는 전부 교사 빨간펜"*. 지문 빈칸 + 교사 빨간펜 + 연필 체크가 한 화면에 겹친 문항이라
판독 난도가 높다. 프롬프트 문구로 풀릴 성질인지는 불확실하다.

## 하네스 버그 1건 — 발견·수정

이 실측을 하다 드러났다. **`--only`로 일부만 돌리면 지표가 실제보다 나쁘게 나온다.**

`scoreRun`이 `groundTruth.pages` 전체를 순회하며 `runOutputs[page.image] || []`로 읽는다.
안 돌린 페이지는 빈 배열이 되어 그 페이지 전 문항이 `abstain`으로 집계됐다.

```
수정 전 (4쪽 기준으로 채점)   mc recall 0.30 · blank_cell recall 0.4211
수정 후 (돌린 2쪽만 채점)     mc recall 0.75 · blank_cell recall 0.8889
```

`run-eval.mjs`는 예측 쪽만 `goldImages`로 걸렀고 `gt`는 그대로 넘겼다(`compare.mjs`·
`baseline-single-call.mjs`·`rescore.mjs`도 동일). 그래서 근본 위치인 `scoreRun`에서 고쳤다.

```js
if (!(page.image in runOutputs)) continue;
```

**키가 없는 것**(안 돌림)과 **키는 있는데 빈 배열**(돌렸는데 0건 추출)을 구분한다. 후자는 종전대로
`missing`으로 처벌한다 — 이 구분이 없으면 파이프라인이 실패한 페이지까지 봐주게 된다.
전체 실행 시에는 모든 페이지 키가 있으므로 **동작이 바뀌지 않는다**(회귀 없음).

회귀 테스트 2건 추가: `test/problemMatching.test.mjs`.

## 후속 측정 — Step 2 모델을 preview → 3.5-flash로 교체

위 측정에는 **어느 모델이 답했는지 기록이 없었다.** 결과 파일에 모델 필드가 없어서 "89.1%가
무엇의 성적인가"를 사후에 확인할 수 없었다(시퀀스에 폴백이 있어 1순위가 답했다는 보장이 없다).
그래서 이번엔 **실제 응답 모델을 결과에 기록하도록 하네스를 먼저 고치고** 다시 쟀다.

바꾼 것은 **Step 2(구조화) 1순위 모델뿐**이다. Step 1(추출)은 양쪽 다 `gemini-3.5-flash`였다.

```
전: STRUCTURE_MODEL_SEQUENCE = ['gemini-3-flash-preview', 'gemini-3.1-flash-lite']
후: STRUCTURE_MODEL_SEQUENCE = ['gemini-3.5-flash',       'gemini-3.1-flash-lite']
```

기록된 실제 모델: **`gemini-3.5-flash → gemini-3.5-flash` 2회, 조합 1종.**
폴백이 한 번도 걸리지 않았으므로 아래 수치는 3.5-flash 단일 모델의 성적이다.

### 결과 — 89.1% → 93.5%

| | 전 (Step2=preview) | 후 (Step2=3.5-flash) |
|---|---|---|
| 필드 정확도 | 41/46 = **89.1%** | 43/46 = **93.5%** |
| `mc_user` / `mc_correct` | 0.75 (wrong 1) | **1.0 (wrong 0)** |
| `multi_*` | 0 (wrong 1) | 0 (wrong 1) — 그대로 |
| `blank_user` / `blank_cell_user` | 0.75 / 0.8889 | 0.75 / 0.8889 — 그대로 |
| `blank_correct` / `text_*` | 1.0 | 1.0 — 그대로 |
| 문항 매칭 · 기권 | 23/23 · 0건 | 23/23 · 0건 |

**23문항 중 예측이 달라진 것은 Q15 하나뿐이고, 그 하나가 정확히 개선됐다.**

```
Q15  전: user="4" correct="5"   (둘 다 오답)
     후: user="3" correct="3"   (둘 다 GT 일치)
```

나머지 22문항은 두 런의 예측이 문자 단위로 동일했다. 앞서 **원인 C(단일 객관식 오독)** 로
분류한 2건이 이걸로 해소됐다 — 지문 빈칸 ⓐ~ⓓ + 교사 빨간펜 + 연필 체크가 겹친 문항이라
"프롬프트로 풀릴지 불확실"이라 적었는데, 프롬프트가 아니라 **모델 교체로 풀렸다.**

Step 1이 동일한데 Step 2 교체만으로 답이 바뀐 점에 주목할 만하다. 같은 추출 텍스트를 놓고
구조화 단계가 답을 잘못 집어냈던 것이지, 이미지 판독 자체의 실패가 아니었다.

### 이 비교의 한계

- **1런 대 1런**이다. 22문항이 문자 단위로 같게 나온 건 `temperature 0.0`에서 재현성이 높다는
  방증이지만, Q15가 원래 런마다 흔들리는 문항이라 우연히 맞았을 가능성을 완전히 배제하지는 못한다.
- **직전 런의 실제 모델은 기록이 없다.** 그 런이 preview로 답했는지, 429로 3.1-flash-lite에
  폴백했는지 알 수 없다. 즉 "preview보다 3.5-flash가 낫다"보다는 **"바꾼 뒤가 더 낫다"** 가
  정확한 서술이다. (모델 기록은 이번 변경으로 다음 측정부터 남는다.)
- 표본은 여전히 2쪽 23문항이다.
