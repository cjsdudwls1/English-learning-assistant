## 판독 규칙

이 세트는 **전 페이지에 교사 빨간펜 채점 흔적**이 있다. 그래서 규칙을 명시했다:

- `user_answer` = **학생의 연필 마킹만**
- 교사의 빨간 V/O/밑줄/정정 필기는 **절대 `user_answer`로 쓰지 않는다**

빨간 정정 필기를 학생 답으로 흡수하면 confident-wrong이 나온다 — 이 표본의 핵심 검출 목표다.
(예: 146쪽 Q8은 보기 ⓐ~ⓔ 위에 교사가 `by`/`in`/`on`을 빨간펜으로 적어놨다. 학생 답은 선택지 ②다.)

## 검수해 주실 것 3 — 규약 판단이 필요한 것

### (1) 143·145쪽 섹션별 번호 재시작 — 하네스가 채점하지 못한다

Unit Exercise는 섹션 A/B/C가 **각각 1부터 다시 번호를 매긴다.** 한 페이지에 `1`이 세 개 있다.

`score.mjs`의 매칭 키가 이걸 감당하지 못한다:

```js
// eval/harness/score.mjs:24
export function normalizeProblemNum(v) {
  const s = String(v).trim();
  const m = s.match(/\d+/);   // 첫 숫자열만
  return m ? m[0] : s;
}
```

`"A-1"` · `"B-1"` · `"C-1"`이 전부 `"1"`이 되고, `byNum` Map에서 **마지막 항목만 살아남는다.**

**추정이 아니라 실측이다.** GT를 그대로 되돌려주는 "완벽 예측"을 `scoreRun`에 넣어 봤다:

```
[빈 출력]   mc 10 abstain, multi 1 abstain, text 33 abstain, multi_gt_invalid 0  — 크래시 없음
[완벽 예측] mc 10/10 correct, multi 1/1 correct, text 19 correct + 14 wrong
```

**완벽한 예측인데 14문항이 wrong으로 찍힌다.** 전부 143·145쪽이고, 예측이 A 섹션 문항인데 GT는 같은 번호의 C 섹션 문항과 대조되는 식이다:

```
05.jpg A-1  gt "on"           vs pred "at night"            → wrong   (C-1과 충돌)
04.jpg A-3  gt "to"           vs pred "is full of fish"     → wrong   (C-3과 충돌)
04.jpg B-1  gt "through,through" vs pred "is good at science" → wrong (C-1과 충돌)
...
```

- **146·147쪽 15문항은 지금 바로 채점 가능** — 완벽 예측에서 `wrong` 0
- **143·145쪽 29문항은 현행 하네스로 정상 채점되지 않는다** (완벽해도 14 wrong)

라벨에는 섹션 접두(`A-1`)를 그대로 살려 뒀다 — 지면의 사실이 그렇기 때문이다. 고치려면 코드 쪽이 바뀌어야 한다:

| 안 | 내용 | 비용 |
|---|---|---|
| (a) 라벨을 1~16 통번호로 바꿈 | 지면과 다른 번호를 GT에 넣게 됨. 모델이 `A-1`을 뭐라 출력하든 맞출 수 없다 | 낮음 / 정확성 손해 |
| (b) `normalizeProblemNum`이 섹션 접두를 보존 | 파이프라인도 섹션을 출력해야 매칭됨 — 추출 프롬프트까지 손봐야 한다 | 중간 |
| (c) 이 2쪽을 GT에서 제외 | 빈칸 서술형·지운 자국 케이스를 통째로 잃음 | 낮음 / 커버리지 손해 |

**추천은 (b)다.** 다만 이번 작업(라벨링) 범위 밖이라 손대지 않았다. 어떻게 할지 정해 주시면 반영한다.

### (2) `multi_blank` 인덱스별 채점은 여전히 미구현

이 세트의 9문항이 `multi_blank`다(143 B-1~3, 145 B-1~4, 146 Q5, 147 Q14).
현행 하네스는 배열을 `', '`로 이어붙인 스칼라로 text 경로 채점을 한다. 143 B-3처럼 **순서만 뒤바뀐 오답**은 이어붙인 문자열이 달라지므로 지금도 오답으로 잡히지만, 부분정답(2개 중 1개만 맞음)은 통째로 오답 처리된다.
`multi_select`와 달리 이건 아직 별개 로직이 필요하다 — 직전 작업에서도 범위 밖으로 뒀다.

## 병합 시 주의

- `_confidence` / `_note` / `_case` / `_case_type` / `_critical_check` / `_harness_note` / `_placeholder` / `answer_key` 등 **밑줄 접두 필드와 `answer_key`는 검수용**이다. `ground-truth.json`에 넣을 땐 제거해야 한다(하네스가 모르는 키).
- `_placeholder: true` 스칼라는 `multi_blank` 9문항에만 있다. text 경로가 스칼라를 참조하므로 유지했다. `multi_select`(147 Q10)에는 없다 — 참값은 배열뿐이다.
- 147쪽에 학생 이름 손글씨("Rami English"는 학원 도장, 그 위 필기는 이름)가 있다. GT 파일 자체엔 이름을 적지 않았다.
- 해설지 2장은 GT `pages`에 넣지 않았다. 학생 답이 없는 정답 원천이므로 라벨 대상이 아니다.
