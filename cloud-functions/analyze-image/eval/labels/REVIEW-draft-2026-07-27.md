## 확정된 규약 (2026-07-27)

### 1. 복수정답 객관식 — `multi_select` 신설 ✅ 확정

표본 중 5문항이 해당("정답 2개", "모두 고르시오").
`answer_format: "multi_select"` + 기존 `user_answers`/`correct_answers` 배열 재사용,
값은 정렬된 문자열 배열(`["3","4"]`).

**코드 지원 완료 (2026-07-27).** 초안 작성 시점에 지적한 두 결손을 모두 메웠다:

| 위치 | 초안 시점 문제 | 조치 |
|------|----------------|------|
| `eval/harness/score.mjs` | `normalizeMC`가 `/[1-5]/`로 첫 숫자만 잘라 `"2, 4"` → `"2"` 절단. `scoreRun`이 `answer_format`을 아예 안 읽음 | `classifyMultiSelect` 집합채점 + `multi_user`/`multi_correct` 버킷 분리 + `multi_gt_invalid` 카운터 |
| `shared/simplePipeline.js` | 복수정답 지시문 없음(구 4-Pass `shared/prompts.js`엔 있었으나 2-스텝 이관 시 누락) | Step 1·2 프롬프트에 복수정답 규칙 복원 + `normalizeItem`이 `multi_select` → DB 계약값 `multi`로 정규화하며 번호집합 정렬·중복제거 |

| `eval/harness/pipeline-runner.mjs`<br>`simulate-grading.mjs` | marks가 스칼라만 실어 집합이 깨짐 | `answer_format`·`user_answers`·`correct_answers` 전달 |

아직 `text_*` 경로를 탄다. 해당 문항의 `_placeholder` 스칼라는 하네스가 여전히 참조하므로 남겨뒀고,

### 2. (A)/(B) 짝 선택지 — 선택지 번호만 ✅ 확정

`112716414`의 Q14·16·17·18처럼 선택지가 `① that - who` 형태인 경우, 정답은 **번호만**(`"2"`).
텍스트 병기 금지 — 채점이 문자열 완전일치라 `(A) who (B) which` 같은 표기는 구분자·공백·괄호 차이로 오탐이 난다.

### 3. 교재에 인쇄된 정답 박스 — correct_answer 1순위 근거 ✅ 확정

인쇄된 `|정답|` 박스는 사람의 어법 추론보다 정확하므로 correct_answer의 1순위 근거로 쓴다.
**user_answer로는 절대 쓰지 않는다.** 프롬프트에 이 구분을 명시해야 한다(현재 없음).
※ 위에서 적었듯 이 규약을 검증할 표본이 현재 GT에 없다.

### 4. 2단 조판 컬럼 넘김 — 내 오독을 정정 ✅ 확정

**정정 내용.** `101043325_05`에서 "우상단의 주인 없는 선택지 뭉치 = 앞 페이지 문항"이라고 판독한 것은 **틀렸다.**
실제로는 **좌컬럼 하단 Q33의 선택지가 우컬럼 상단으로 이어진 것**이다. 같은 페이지 안에서의 컬럼 넘김이다.

정정 전후:

| | 정정 전 (오독) | 정정 후 |
|---|---|---|
| 가짜 Q31 | user `④`, correct `null` | **항목 삭제** |
| Q33 | user `null`, correct `null` ("선택지가 다음 페이지로 넘어감") | user **`4`**, correct **`1`** |

Q33 지문은 "the individual actively has to ______. The search for the right song is thus associated with considerable effort."
정답 ① `choose and determine his or her musical preferences`, 학생 마킹 ④ → **학생 오답 케이스**로 GT에 남는다.

**규약**: 2단 조판에서 좌측 컬럼 하단 문항의 선택지는 우측 컬럼 상단으로 이어진다.
"앞 페이지 문항"으로 오독하지 않는다. 선택지가 **이 이미지에 실제로 없는** 문항만 null 라벨(이 장에서는 Q35 하나).

이 정정으로 이 장은 "페이지 경계" 케이스가 아니라 **"컬럼 넘김 추적" 케이스**가 됐다.
파이프라인이 컬럼 순서를 못 따라가면 Q33이 선택지 없는 문항으로 보이고 우상단 뭉치는 주인 없는 선택지로 오인된다 — 이것이 이 장의 검출 목표다.


완벽 예측에서 `wrong`이 하나도 남지 않으므로 라벨 형태 자체에 채점 불가 케이스는 없다.
